# doc-buddy · AI 文档搭子

对话采集一次需求，一键生成 **BRD / MRD / PRD** 三类产品文档。

> 起因：我先手写完了企业级 AI 产品 SmartTender 的 BRD、MRD、PRD 全套文档，
> 发现三类文档的输入其实是同一份需求信息、只是视角不同——于是把这套写法做成了工具。

---

## 三类文档分别回答什么

| 文档 | 读者 | 回答 | 10 章结构要点 |
|------|------|------|---------------|
| **BRD** 商业需求文档 | 决策层 / 资源审批方 | 为什么值得做 | 商业背景与战略契合、商业目标与成功指标、成本收益与 ROI 测算、商业模式、In-Scope / **Out-of-Scope**、风险合规、**Go / 条件性 Go / No-Go** 建议 |
| **MRD** 市场需求文档 | 产品与市场团队 | 凭什么赢 | 市场定义、**TAM / SAM / SOM**、用户分层与画像、痛点 **KANO 分类**、竞品对比与**启示**、差异化定位、关键假设与验证方式 |
| **PRD** 产品需求文档 | 研发 | 怎么做 | 产品概述、用户场景、功能需求（含优先级与对应痛点）、**Mermaid 流程图**、数据需求、界面建议、技术考量、里程碑、风险与假设 |

同一份需求信息，三种视角输出——这正是产品经理的核心基本功。

## 架构：对话引导 → 文档生成

```
用户输入
   │
   ▼
┌──────────────────────────────────────────┐
│ 引导层  prompts/chat-guide.md            │
│ · 基于「新 5 要素」模型做完整性校验       │
│   产品名称 / 目标用户 / 痛点与需求 /      │
│   核心解决方案 / 核心交互逻辑             │
│ · 缺什么追什么，按优先级一次只追 1-2 项   │
│ · 追问必须带选项或场景示例（禁止直白提问）│
│ · 输出可点击的 quick_options              │
└──────────────────────────────────────────┘
   │  五要素集齐
   ▼
┌──────────────────────────────────────────┐
│ 生成层  prompts/generate-{brd,mrd,prd}.md│
│ · 固定章节结构，保证每次输出一致          │
│ · 强制 Mermaid 流程图与表格化表达         │
│ · 数字必须标注来源或标为「（假设）」      │
└──────────────────────────────────────────┘
   │
   ▼
解析层：JSON 容错（尾逗号修复等）→ 失败走降级路径，不把错误结果交给用户
   │
   ▼
导出：Markdown / Word / PDF
```

**每次模型调用全量落盘日志**到 `logs/ai-calls-YYYY-MM-DD.jsonl`：
提示词版本、完整输入输出、token、耗时、状态。没有日志就无法判断
"这次生成变好了"是真的变好了还是随机波动，提示词迭代会变成玄学。

## 快速开始

```bash
npm install

# 复制配置模板并填入 API Key（config.js 不会进 git）
cp config.example.js config.js

node server.js
# 打开 http://localhost:3000
```

也可用环境变量注入，避免把 Key 写进文件：

```bash
# Windows PowerShell
$env:GLM_API_KEY="你的key"

# Git Bash / WSL
export GLM_API_KEY="你的key"
```

### 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/chat` | 对话引导，返回追问与已提取的 5 要素 |
| POST | `/api/generate` | 生成文档，`body.doc_type` 取 `brd` / `mrd` / `prd`（默认 `prd`） |
| GET | `/api/doc-types` | 获取可用文档类型 |
| GET | `/api/health` | 健康检查 |

## 设计与取舍

**为什么先做「引导」再做「生成」？**
生成质量的上限由输入质量决定。新手真正的困难不是写不出话，是不知道该想清楚什么。
所以引导层做的是"逼你把 5 个要素想清楚"，这比反复优化生成提示词更有效。

**为什么追问必须带选项？**
直接问"你的核心交互逻辑是什么"，用户答不上来。改成
"是像 ChatGPT 那样对话式一步步改，还是像 Word 那样上传后直接标红？"——用户立刻能选。
这是提示词里最容易忽略、但对体验影响最大的一条。

**定位是「从 0 到 0.7」，不是「从 0 到 1」。**
它解决的是空白页恐惧和结构不规范；关键判断（市场数字、ROI、优先级）仍然要人来拍。
这也是为什么模板强制要求所有数字标注来源或标为假设——工具不能替产品经理承担责任。

## 已知限制

- 生成质量依赖模型能力，长文档偶发章节缺失，需人工复核
- 未做多轮修改能力，目前是"一次生成 + 人工编辑"
- 日志明文存储输入输出，若用于真实业务需先做脱敏
